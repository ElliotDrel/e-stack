# Build a Work Brief

Use this guide when the user wants a fuller prompt for work that has meaningful
scope, context, or decision criteria. Build from the user's existing material
before asking questions.

## Work with the actual gap

Identify the outcome first. Then add only the details that would change the
result: audience, current context, source material, constraints, quality cues,
and the expected stopping point. Treat these as prompts for judgment, not a form
the user must complete.

Ask focused follow-ups only where an answer materially changes the brief. If the
goal is still undecided, use `task-shaper.md`. If the user needs a finish line,
use `definition-of-done-generator.md`. Continue building the brief when that
answer is available; do not require a new ceremony or repeat questions already
answered.

## Write the brief

Write in the form most useful to the recipient: a short paragraph, a compact
list, or another format the user requests. A strong brief makes clear:

- the outcome and who it serves;
- the supplied sources or facts to rely on;
- important boundaries and preferences; and
- the useful deliverable and any intended checkpoint.

Use the shortest wording that keeps those choices clear. For time-sensitive or
factual work, say which sources to use or ask the worker to verify what needs to
be current. Do not invent evidence, requirements, or a citation plan the user
did not request.

Show the draft in chat and revise it from the user's feedback. An optional audit
with `vague-ask-auditor.md` can help for consequential work, but it is not a
required second pass.
