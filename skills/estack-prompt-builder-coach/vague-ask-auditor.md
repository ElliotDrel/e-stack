# Audit a Draft Request

Use this guide when the user has a request that may leave important choices to
guesswork.

Read the draft and identify what is already clear, the few missing details most
likely to change the result, and any words that carry multiple plausible
meanings. Explain the likely consequence of each material gap. Do not manufacture
problems to fill a generic checklist.

Ask only the questions needed to resolve those gaps. Then provide a revised
request that keeps the user's tone and uses their answers. It can be shorter than
the original when that makes the intent clearer. Show a compact before-and-after
view when it helps the user evaluate the edit.

For a request that is already sufficient for its stakes, say so and make only
the requested refinements. Save or run the resulting work only when the user
asks.
