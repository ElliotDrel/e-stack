# Define Done

Use this guide when the user knows the goal but needs a clear finish line for
the work.

Start from the task and information already provided. Ask only about missing
details that change completion: who will use the result, what decision or action
it supports, what must be present, and where this task should stop. Do not repeat
questions the user has already answered.

Write a definition of done at the level the task needs. It may be a single
sentence for a small request or a compact set of criteria for work with several
stages. Include, where relevant:

- the deliverable and its intended audience;
- the information or behavior that makes it complete;
- the quality cues the user cares about;
- any review point; and
- a boundary with adjacent work.

Use the user's language and make criteria observable when that helps. Flag a
bundled request only when splitting it would make the deliverable clearer. Return
to the broader brief only if the user wants one; defining done can be the final
deliverable on its own.
