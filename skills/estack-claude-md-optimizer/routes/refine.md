# Refine Existing Project Instructions

Read the file the user wants to improve and inspect only the surrounding project
material needed to judge its accuracy. Preserve the project's canonical
`AGENTS.md`/`CLAUDE.md` architecture unless changing it is part of the request.

Review the requested scope for instructions that are stale, duplicated,
ambiguous, missing important rationale, or no longer useful. Keep instructions
that still communicate durable intent. Use a light keep, clarify, remove, or add
assessment when it makes the proposed edit easier to review; do not require a
whole-file classification or deletions to prove an audit happened.

Explain material edits with their evidence, then make the authorized targeted
changes. Verify any commands, paths, and linked documents affected by the edit.
If an instruction's meaning depends on a user preference that the repository
cannot establish, ask that focused question rather than guessing.
