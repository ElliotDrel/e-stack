# Path A: The Sponsorship Packet

Read `references/03-sponsorship-market.md` (the 6-page template and the 10 mistakes) and `references/06-storybrand-messaging.md` before drafting; `references/07-start-with-why.md` governs the opening. The finalized offer file from Phase 1 is the input — the packet is the offer in document form, so nothing goes in the packet that isn't in (or consistent with) the offer.

## What this path produces

`sponsorship-packet.md`: complete, final copy for every page, ready to be laid out as a PDF. For each page give a layout note (one or two lines on visual intent) and then the actual copy — the user should be able to paste into a design tool without writing another sentence.

## Ground rules before drafting

- **Position it honestly with the user:** per the research, the packet does not sell the sponsorship; people do. It's a conversation tool sent *after* contact, and it must never be attached to a cold email. Say this once so the user deploys it correctly.
- Every page passes the Value Equation test (raises outcome, raises likelihood, cuts time, or cuts effort) and the three-question test (what's on offer, how it improves their situation, what to do next — answerable in seconds).
- The sponsor is the hero on every page; the org is the guide. Org-history essays, mission-statement pages, and board lists don't survive.
- No gold/silver/bronze anywhere. No tear-off payment form. Never titled "Sponsorship Package".

## Page-by-page structure

Follow the 6-page practitioner template, StoryBrand-shaped:

1. **Cover** — opportunity name (the MAGIC name from the offer), org logo, the one-liner as tagline, one direct CTA line.
2. **The audience** — before anything about the org. Real numbers, meaningful segments, engagement data. This is the product; treat the page like a spec sheet, not a collage. Unverified numbers do not ship — resolve or cut every `[assumption — verify]` flag with the user here.
3. **The story** — why-first: the belief (2–3 sentences), the how, then the event/program in one paragraph as proof of the belief. Then the sponsor's problem framed in StoryBrand's three layers (external/internal), and the guide move: one empathy line + authority proof (past sponsors, outcomes, testimonials).
4. **The menu** — action-framed asset groups from the offer stack ("Build your engineering intern pipeline", "Put your product in front of X"), opened with the working-philosophy statement: these are starting points, and the org builds custom packages from conversation. Components carry stated values where the offer does. The three options can appear here as examples of how packages come together — labeled as examples, priced, anchor first.
5. **Sample activations** — 4–6 concrete ideas (branding, sampling, experience, contest, content) that show sophistication and start the sponsor thinking. These can include good inventory items that didn't make the core stack.
6. **The plan + the ask** — the ≤4-step process plan ("Discovery call → we design your package → we run everything → you get the report"), the named guarantee, the why-now, and the contact page: warm, "this is the start of a conversation", direct CTA (book the call) plus a transitional CTA (get the audience report). 

Six content pages is the ceiling, per the research. If the user wants more, the burden is on each extra page to pass the Value Equation test.

## Working style

Draft page by page, checking in after each page or two rather than delivering all six in one block — the audience page and the menu page in particular need the user's real data and will shape everything after them. Apply the user's brand rules from Phase 1 throughout. Where proof doesn't exist yet (first-year property), say so in the copy honestly (StoryBrand authority can come from the team and the plan) rather than inflating.

## Done when

Every page has layout note + final copy; no unresolved assumption flags; each page names its one next step; the packet contradicts nothing in `sponsorship-offer.md`; and the user has confirmed page-level copy, not just the outline.
