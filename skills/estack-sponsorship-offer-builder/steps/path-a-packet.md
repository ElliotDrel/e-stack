# Path A: The Sponsorship Packet

Read `references/03-sponsorship-market.md` (the 6-page template and packet mistakes) and `references/06-messaging.md` first. Input: the finalized offer file — the packet is the offer in document form, so nothing goes in it that isn't consistent with the offer.

**Output:** `sponsorship-packet.md` — complete final copy for every page, each with a one-line layout note, ready to paste into a design tool without writing another sentence.

## Ground rules

- **Position it honestly with the user, once:** proposals don't sell sponsorship, people do. The packet is a conversation tool sent *after* contact — never attached to a cold email.
- Every page passes two tests: the Value Equation (raises outcome or likelihood, or cuts time or effort) and the three-question test (what's on offer, how it improves their situation, what to do next — answerable in seconds).
- No gold/silver/bronze. No tear-off payment form. Never titled "Sponsorship Package". Org-history essays and board lists don't survive.

## Page-by-page (6 pages, the ceiling)

1. **Cover** — opportunity name (the MAGIC name from the offer), org logo, the one-liner as tagline, one direct CTA line.
2. **The audience** — before anything about the org; it's what the sponsor is buying. Real numbers, meaningful segments, engagement data, treated like a spec sheet. Resolve or cut every `[assumption — verify]` flag with the user here — unverified numbers do not ship.
3. **The story** — why-first: the belief in 2–3 sentences, the how, the event in one paragraph as proof. Then the sponsor's problem in StoryBrand's external/internal layers, and the guide move: one empathy line + authority proof.
4. **The menu** — action-framed asset groups from the offer stack ("Build your engineering intern pipeline"), opened with the working-philosophy statement: these are starting points and the org builds custom packages from conversation. The three options can appear as priced examples, anchor first.
5. **Sample activations** — 4–6 concrete ideas (branding, sampling, experience, contest, content) that show sophistication and start the sponsor thinking. Good inventory items that didn't make the core stack live here.
6. **The plan + the ask** — the ≤4-step process plan, the named guarantee, the why-now, and a warm contact page framed as "the start of a conversation": direct CTA (book the call) plus transitional CTA (get the audience report).

If the user wants more pages, each extra one must pass the Value Equation test.

## Working style

Draft page by page, checking in every page or two — the audience and menu pages need the user's real data and shape everything after them. Apply the brand rules from Phase 1. Where proof doesn't exist yet (first-year property), say so honestly in the copy; authority can come from the team and the plan.

## Done when

Every page has layout note + final copy; no unresolved assumption flags; each page ends in one next step; nothing contradicts `sponsorship-offer.md`; the user confirmed page-level copy, not just the outline.
