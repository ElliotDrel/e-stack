# Phase 1: Build the Offer (Core Deliverable)

Read `references/01-hormozi-value-equation.md` and `references/02-positioning-and-pricing.md` before running this phase; pull `references/06-storybrand-messaging.md` for the one-liner and `references/07-start-with-why.md` for the why-first framing. Phase 0's outputs (why, inventory, sponsor profile) are the inputs here — if they don't exist yet, go back.

This phase runs Hormozi's 5-step process on the sponsor profile, prices it with Enns' option structure, and writes the result to a Markdown file. Work step by step with the user; each step ends with something concrete they've agreed to.

Ask once, at the start: any brand rules for written output (name casing, banned punctuation, voice)? Apply them to everything from here on.

## 1. Dream outcome

For the primary sponsor profile from Phase 0: what outcome would make their buyer look great to their own boss? Push past "exposure" to the metric the buyer is judged on (hires made, qualified leads, product adoption, brand position with this audience). Write it as one sentence in the sponsor's voice: "We got X by Y."

## 2. Problem list

List everything that stops that sponsor getting the outcome today, sorted by the four levers: not worth it (outcome), won't work (likelihood), too slow (time), too hard (effort). Include the problems with the *status quo alternatives* — job boards, career fairs, ad spend — because the offer is judged against those, not against nothing.

## 3. Solutions from the inventory

Map Phase 0 assets onto the problem list: for each real problem, which asset kills it? Problems with no asset are either dropped from the promise or become new assets to build. Assets that solve no problem stay out of the offer (they can pad Path A's activation menu instead).

## 4. Delivery design

For the 2–3 highest-value solutions, run the Delivery Cube questions: who does the work (aim done-for-you — the sponsor writes a check and shows up), how fast is first value (deliver something before the event: an intro, a data report, early access), what's the format, what does 10x-price service look like and what survives at 1/10th. This step is where "logo placement" turns into "we run your entire recruiting touchpoint for the semester".

## 5. Trim and stack

Cut high-cost/low-value and low-cost/low-value items. Bundle the survivors into 3–5 **named components** (MAGIC naming: 3–5 of magnet/avatar/goal/interval/container — "The Spring Engineering Talent Pipeline", not "Recruiting Package"). Each component gets a stated value with a one-line justification. The stack's total stated value should be a large multiple of the ask.

## 6. Risk reversal

Pick a guarantee the org can actually honor (reference 01's four types). Sponsorship-shaped defaults: the make-good (any undelivered asset is replaced with one of equal or greater value), the extended-service guarantee (we keep promoting until the number is hit), credit toward next season. Name it. If the org has strong confidence and tracking, offer a conditional performance guarantee on the one metric that defines the dream outcome. Never promise what fulfillment can't verify — the metric-integrity rules in reference 03 govern what can be guaranteed.

## 7. Price with three options

Run Enns' structure (reference 02): Option 3 the true anchor (exclusivity, year-round, full service — priced where it's genuinely worth doing, presented first, not expected to sell), Option 2 the target built in steps 1–6, Option 1 a smaller real package. Options differ by scope and access, never by effort or enthusiasm. Sanity-check the target price against the asset valuations from Phase 0 and any comparable-property data. Note the reason-to-act-now: the real deadline (event date, print date, exclusivity being single-seat). No invented scarcity.

## 8. Write the file

Write `sponsorship-offer.md` (or the user's chosen path) with exactly these sections:

1. **One-liner** — the StoryBrand template filled in.
2. **Why** — 2–3 sentences, belief first, event as proof.
3. **Who this is for** — the sponsor profile, named segments, example companies, the buyer role and their metric.
4. **The dream outcome** — in the sponsor's voice.
5. **The offer stack** — each named component: what it is, the problem it kills, delivery, stated value.
6. **The guarantee** — named, with its exact terms.
7. **The three options** — table: option name, what's in it (by component), price. Anchor first.
8. **Why now** — the true deadline and any true caps.
9. **Proof we'll lean on** — the evidence available today (data, past sponsors, testimonials) and gaps to fill.
10. **Assumptions to verify** — every `[assumption — verify]` item carried forward, in one list.

Every claim traces to a Phase 0 answer or carries the assumption flag.

## Acceptance bar

The offer is done only when: the file exists; a named sponsor profile with real example companies is in it; every stack component maps to a discovered problem; there's a named guarantee; three priced options exist with the anchor first; the why-now is literally true; and the assumptions list is explicit. Check the stack against the Value Equation one last time: does each component raise outcome or likelihood, or cut time or effort? Cut anything that doesn't.

Then offer the paths, by name, in one short block: **Path A** — the sponsorship packet. **Path B** — the cold email chain. **Path C** — the meeting script. Any, all, or none.
