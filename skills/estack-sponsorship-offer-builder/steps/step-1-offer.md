# Phase 1: Build the Offer (Core Deliverable)

Read `references/01-hormozi-value-equation.md` and `references/02-positioning-and-pricing.md` before this phase; pull `references/06-messaging.md` for the one-liner and why-first framing. Inputs: Phase 0's why, inventory, and sponsor profile — if they don't exist, go back.

This phase runs Hormozi's 5-step process on the sponsor profile, prices it with Enns' option structure, and writes the result to a file. Work step by step; each step ends with something the user has agreed to. Ask once at the start: any brand rules for written output?

## 1. Dream outcome

What outcome would make the buyer look great to their own boss? Push past "exposure" to the metric they're judged on (hires, qualified leads, adoption, brand position). Status is the deepest layer — frame the benefit in how *others* will see their win. Write it in the sponsor's voice: "We got X by Y."

## 2. Problem list

Everything that stops that sponsor today, sorted by the four levers: not worth it, won't work, too slow, too hard. Include the problems with the status-quo alternatives (job boards, career fairs, ad spend) — the offer is judged against those, not against nothing.

## 3. Solutions from the inventory

For each real problem, which Phase 0 asset kills it? Problems with no asset are dropped from the promise or become assets to build. Assets that solve no problem stay out (they can pad Path A's activation menu). Solve *every* problem the sponsor will perceive — any single unhandled obstacle can be the quiet reason for a no, and a one-time fix (a pre-approved brand-use sheet) removes it for every future sponsor.

## 4. Delivery design

For the 2–3 highest-value solutions, run the Delivery Cube: who does the work (aim done-for-you — the sponsor writes a check and shows up), how fast is first value (engineer a fast win close to signing: an intro, a data report, early access), format, the 10x / 1/10th test. Favor one-to-many assets built once and delivered to every sponsor (the audience report, the resume book). This step is where "logo placement" becomes "we run your entire recruiting touchpoint for the semester".

## 5. Trim and stack

Cut high-cost/low-value, then low-cost/low-value. Bundle the survivors into 3–5 **named components** (MAGIC naming — "The Spring Engineering Talent Pipeline", not "Recruiting Package"), each with a stated value and one-line justification. Total stated value should be a large multiple of the ask.

## 6. Risk reversal

Pick a guarantee the org can actually honor (reference 01's four types). Sponsorship defaults: the make-good (undelivered asset replaced at equal or greater value), extended service (we keep promoting until the number is hit), credit toward next season. Name it. Only guarantee what fulfillment can verify (reference 03's metric-integrity rules).

## 7. Price with three options

Enns' structure (reference 02): Option 3 the anchor, presented first (exclusivity, year-round, full service — priced where it's genuinely worth doing, not expected to sell); Option 2 the target built in steps 1–6; Option 1 a smaller real package, never a throwaway. Options differ by scope and access, never by effort. Sanity-check the target price against Phase 0's asset valuations. Note the reason to act now — the real deadline only; no invented scarcity.

## 8. Write the file

`sponsorship-offer.md` (or the user's path), sections in order:

1. **One-liner** (StoryBrand template)
2. **Why** — 2–3 sentences, belief first, event as proof
3. **Who this is for** — profile, example companies, buyer role and their metric
4. **The dream outcome** — in the sponsor's voice
5. **The offer stack** — each named component: what it is, the problem it kills, delivery, stated value
6. **The guarantee** — named, exact terms
7. **The three options** — table, anchor first, priced
8. **Why now** — the true deadline and any true caps
9. **Proof we'll lean on** — evidence available today, gaps to fill
10. **Assumptions to verify** — every flagged item, one list

## Acceptance bar

Done only when: the file exists; a named profile with real example companies is in it; every component maps to a discovered problem; a named guarantee; three priced options, anchor first; a literally-true why-now; an explicit assumptions list. Final check: each component moves a Value Equation lever, or it gets cut.

Then offer the paths in one block: **Path A** — the packet. **Path B** — the cold email chain. **Path C** — the meeting script.
